# Bugfix Checklist

버그 수정 작업 시 따라야 하는 체크리스트.

이 문서는 화면 깨짐, API 오류, 경로 문제, 데이터 조회 이상, 권한/예외 처리 문제 등
`mySptPrj`의 일반적인 버그 수정 흐름을 대상으로 한다.

## 1. 작업 시작 전

- [ ] 버그 증상과 재현 경로를 명확히 확인했다.
- [ ] 화면 문제인지, 백엔드 문제인지, 연동 문제인지 1차 분류했다.
- [ ] 관련 도메인과 파일 위치를 찾았다.
- [ ] 유사 기능/유사 화면도 있는지 확인했다.
- [ ] 최근 변경 이력이나 관련 문서가 있는지 확인했다.

## 2. 원인 파악

- [ ] 증상과 원인을 구분했다.
- [ ] 실제 원인이 템플릿 / CSS / JS / Controller / Service / Mapper / 설정 중 어디에 있는지 좁혔다.
- [ ] 하드코딩된 경로, 잘못된 selector, 누락된 model 값, 잘못된 SQL, 예외 처리 누락 등을 점검했다.
- [ ] 관련 로그, 조건문, 분기 처리, null 처리 여부를 확인했다.

## 3. 수정 원칙

- [ ] 원인 해결에 필요한 범위만 수정한다.
- [ ] 증상만 가리는 임시 코드보다 원인 해결을 우선한다.
- [ ] 기존 구조를 깨는 대규모 리팩터링은 섞지 않는다.
- [ ] 신규 규칙이나 예외 처리가 필요하면 관련 문서 갱신 여부를 함께 판단한다.

## 4. 영역별 확인 포인트

### UI / 템플릿
- [ ] 존재하지 않는 정적 리소스 참조가 없는가?
- [ ] 공통 레이아웃/fragment와 충돌하지 않는가?
- [ ] DOM 변경이 JS selector에 영향을 주지 않는가?

### JavaScript
- [ ] 이벤트 바인딩 대상이 실제 DOM과 일치하는가?
- [ ] API 응답 형태를 잘못 가정하고 있지 않은가?
- [ ] 비동기 처리 순서나 null/undefined 처리 문제가 없는가?

### Controller / Service
- [ ] Controller가 DAO를 직접 호출하지 않는가?
- [ ] Service에서 필요한 검증/예외 처리가 누락되지 않았는가?
- [ ] model attribute / redirect 경로 / 응답 구조가 올바른가?

### DAO / Mapper / SQL
- [ ] XML Mapper 경로와 id가 일치하는가?
- [ ] 조회/등록/수정/삭제 SQL이 실제 요구사항과 맞는가?
- [ ] 파라미터명과 VO 필드명이 일치하는가?

### 설정 / 공통
- [ ] profile, properties, 공통 예외 처리, interceptor/filter 영향이 있는가?
- [ ] 공통 유틸이나 보안/세션 처리 영향이 있는가?

## 5. 연관 영향 점검

- [ ] 같은 도메인의 목록/상세/등록/수정 화면도 영향이 없는지 확인했다.
- [ ] 같은 유형의 에러 페이지/공통 화면에도 동일 문제가 있는지 확인했다.
- [ ] 공통부 수정 시 다른 화면 영향 범위를 생각했다.

## 6. 검증 포인트

- [ ] 버그 재현 경로에서 문제가 사라졌는가?
- [ ] 기존 정상 동작이 깨지지 않았는가?
- [ ] 관련 유사 기능도 함께 확인했는가?
- [ ] 변경 이유를 코드와 문서 기준으로 설명할 수 있는가?

## 7. 작업 결과 요약 형식

작업 완료 후 아래 형식으로 요약할 수 있어야 한다.

### 변경 파일
- 어떤 파일을 수정했는지

### 원인
- 왜 문제가 발생했는지

### 조치
- 어떤 방식으로 수정했는지

### 검증 포인트
- 사용자가 무엇을 확인하면 되는지

## 8. 금지 체크

- [ ] 증상만 가리는 임시 주석/하드코딩으로 끝내지 않았다.
- [ ] 관련 없는 리팩터링을 섞지 않았다.
- [ ] `target/` 등 산출물을 수정하지 않았다.
- [ ] 문서와 충돌하는 새 규칙을 암묵적으로 만들지 않았다.
