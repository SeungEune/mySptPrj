# UI Fix Checklist

화면 깨짐, 스타일 불일치, 에러 페이지 정리, 레이아웃 수정 등 UI 작업 시 따라야 하는 체크리스트.

## 1. 작업 시작 전

- [ ] 요청받은 화면 또는 경로를 명확히 확인했다.
- [ ] 관련 템플릿 파일을 찾았다.
- [ ] 연결된 CSS / JS 파일을 확인했다.
- [ ] 유사한 화면 또는 같은 유형의 페이지를 확인했다.
- [ ] 공통 레이아웃 / fragment 사용 여부를 확인했다.

## 2. 문제 파악

- [ ] 실제 문제를 구조 문제 / 스타일 문제 / 리소스 문제로 구분했다.
- [ ] 없는 리소스 참조 여부를 확인했다.
- [ ] 기존 디자인 시스템과 어떤 점이 어긋나는지 정리했다.
- [ ] 화면 단독 문제인지, 같은 유형 페이지 전반 문제인지 판단했다.

## 3. 수정 원칙

- [ ] 기존 공통 스타일을 먼저 재사용했다.
- [ ] 새 CSS는 꼭 필요한 경우에만 추가했다.
- [ ] 기존 JS selector나 id/class에 영향이 없는지 확인했다.
- [ ] 관련 없는 리팩터링을 섞지 않았다.
- [ ] 현재 프로젝트의 문구 톤을 유지했다.

## 4. 연관 영향 점검

- [ ] 같은 유형의 페이지도 함께 확인했다.
  - 예: 403 / 404 / 500
  - 예: 목록 / 상세 / 모달
- [ ] 공통 fragment 수정 시 영향 범위를 고려했다.
- [ ] 경로, 버튼 이동, 리다이렉트 링크가 올바른지 확인했다.

## 5. 검증 포인트

- [ ] 로고 / 아이콘 / 이미지가 정상 노출된다.
- [ ] 버튼 스타일과 동작이 정상이다.
- [ ] 텍스트 계층(제목/본문/안내문구)이 자연스럽다.
- [ ] 모바일 또는 좁은 폭에서 기본적인 레이아웃 문제가 없다.
- [ ] 깨진 경로 또는 예전 자산 참조가 없다.

## 6. 작업 결과 요약 형식

작업 완료 후 아래 항목을 요약할 수 있어야 한다.

### 변경 파일
- 어떤 파일을 수정했는지

### 변경 이유
- 무엇이 문제였고 왜 그렇게 바꿨는지

### 검증 포인트
- 사용자가 무엇을 확인하면 되는지

## 7. UI 작업 시 자주 보는 위치

- 템플릿: `src/main/resources/templates/thymeleaf/`
- 공통 레이아웃: `src/main/resources/templates/thymeleaf/cmm/layout/`
- 공통 CSS: `src/main/resources/static/css/common.css`
- 공통 컴포넌트 CSS: `src/main/resources/static/css/components.css`
- 화면별 CSS: `src/main/resources/static/css/`
- 화면별 JS: `src/main/resources/static/js/`

## 8. 금지 체크

- [ ] `target/` 파일을 수정하지 않았다.
- [ ] 없는 CSS/이미지/JS 경로를 추가하지 않았다.
- [ ] 기존 시스템과 동떨어진 단독 디자인을 만들지 않았다.
- [ ] 설명 없이 예외성 인라인 스타일을 장기 해법처럼 남기지 않았다.
