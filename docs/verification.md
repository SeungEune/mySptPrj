# Verification Guide

`mySptPrj`의 최소 검증 루틴 문서.

이 문서는 현재 프로젝트에서 **가장 적은 비용으로 가장 기본적인 안정성을 확인하는 방법**을 정리한다.
지금 단계에서는 테스트가 많지 않으므로, 빌드 성공 여부와 변경 유형별 수동 확인 포인트를 함께 관리한다.

## 1. 기본 원칙

- 검증은 가능한 한 **작업 직후 바로** 수행한다.
- 변경 크기에 따라 검증 수준을 나눈다.
- 현재는 `mvnw` 기준 명령을 공식 검증 진입점으로 사용한다.
- 테스트가 적은 상태이므로, 빌드 + 수동 확인을 함께 본다.

## 2. 검증 레벨

## Level 1. 빠른 확인

작은 화면 수정, 문구 수정, CSS 수정, 단순 템플릿 수정 직후 수행한다.

```bash
./mvnw -DskipTests package
```

### 목적
- 컴파일/패키징이 깨지지 않았는지 확인
- 템플릿/리소스 변경 후 기본 빌드가 통과하는지 확인

### 추가 수동 확인
- 변경한 화면이 실제로 정상 렌더되는지
- 버튼/링크/문구가 의도대로 보이는지
- 브라우저 콘솔 에러가 없는지

---

## Level 2. 기본 검증

백엔드 로직 수정, 화면과 로직이 같이 바뀐 경우, 공통부 수정 시 수행한다.

```bash
./mvnw test
```

### 목적
- 현재 존재하는 테스트 기준으로 회귀 여부 확인
- 최소한의 프로젝트 정상성 확인

### 추가 수동 확인
- 관련 화면 또는 기능 재현 경로 확인
- 유사 화면/유사 기능 영향 확인
- 로그/에러 페이지 동작 확인

---

## Level 3. 배포 전 확인

배포 직전 또는 큰 변경 묶음 반영 전 수행한다.

```bash
./mvnw package
```

### 목적
- 테스트 포함 전체 패키징 확인
- 실제 배포 산출물 생성 가능 여부 확인

### 추가 수동 확인
- 주요 화면 진입
- 로그인/메인/주요 목록 화면 확인
- 최근 수정 기능 정상 동작 확인
- 에러 페이지/예외 케이스 확인

---

## 3. 작업 유형별 권장 검증

| 작업 유형 | 최소 권장 명령 | 추가 확인 |
|---|---|---|
| 문구 수정 | `./mvnw -DskipTests package` | 화면 렌더 확인 |
| CSS/UI 수정 | `./mvnw -DskipTests package` | 유사 화면 / 브라우저 확인 |
| 템플릿 구조 수정 | `./mvnw -DskipTests package` | JS selector 영향 확인 |
| Controller 수정 | `./mvnw test` | 화면/redirect/model 확인 |
| Service/DAO/Mapper 수정 | `./mvnw test` | 기능 재현 경로 확인 |
| 공통부 수정 | `./mvnw test` | 영향 화면/기능 넓게 확인 |
| 배포 전 | `./mvnw package` | 주요 기능 smoke check |

## 4. 수동 확인 체크리스트

### UI 변경 시
- [ ] 변경 화면이 정상 렌더된다.
- [ ] 레이아웃이 깨지지 않는다.
- [ ] 버튼/링크가 정상 동작한다.
- [ ] 관련 유사 화면도 같이 확인했다.

### 백엔드 변경 시
- [ ] 요청 경로가 정상 동작한다.
- [ ] model attribute / 응답 구조가 정상이다.
- [ ] 예외/빈 값/null 처리에서 문제 없다.
- [ ] Mapper / SQL 연계가 끊기지 않았다.

### 공통 변경 시
- [ ] 다른 도메인에도 영향이 없는지 확인했다.
- [ ] 로그인/메인/공통 화면을 확인했다.
- [ ] 에러 페이지/공통 레이아웃에 문제 없다.

## 5. 커밋 전 최소 권장 루틴

현재 기준 권장 순서:

```bash
./mvnw -DskipTests package
```

변경이 화면 수준을 넘는다면:

```bash
./mvnw test
```

그리고 아래를 확인한다.
- 변경 이유를 설명할 수 있는가?
- 검증 포인트를 설명할 수 있는가?
- 관련 문서 업데이트가 필요한가?

## 6. 현재 한계

이 프로젝트는 아직 테스트 수가 충분하지 않다.
따라서 `./mvnw test`가 통과하더라도 완전한 안전을 의미하지는 않는다.
현재 단계에서 검증은 다음 조합으로 본다.

- Maven 빌드/테스트 명령 통과
- 작업 유형별 수동 확인
- 관련 체크리스트 확인
